# Order DDD 实现计划

**Goal:** 将 Order 下单实现调整为已确认的轻量 DDD 四层结构。

**Architecture:** REST → 应用编排 → 纯 Java 领域模型/仓储接口，基础设施实现商品网关和仓储。

**Tech Stack:** Java 21、Spring Boot、MyBatis-Plus、Sa-Token、RestClient。

- [x] 新建 domain/model 的 Order、OrderStatus、GoodsSnapshot，将创建规则放入工厂方法；新增领域异常及仅支持新建的仓储接口。
- [x] 新建 application/command/CreateOrderCommand、application/port/GoodsGateway、application/service/OrderApplicationService，只协调领域模型和端口。
- [x] 将数据库实体/Mapper 移至 infrastructure/persistence，增加仓储映射；将客户端改为 infrastructure/remote/HttpGoodsGateway，把 HTTP 和价格转换隔离在适配器。
- [x] Controller、请求响应和异常处理移至 interfaces/rest，身份读取放在 Controller，配置移至 infrastructure/config；删除原路径下已迁移的源文件。
- [x] 补充 docs/order.md 分层与调用关系，运行 mvn -B -ntp -pl jaycong-business/jaycong-order -am clean package -DskipTests，并以独立配置入口启动后手工检查 401/400。

验证结果：clean package -DskipTests 构建成功；独立配置入口禁用 Nacos 后启动在 18086，手工 HTTP 验证有效请求未登录为 401，缺少 goodsId、goodsId=0、超长备注为 400。临时进程已停止。未验证登录后商品调用和数据库落库，未新增或修改测试代码。
