# A 调 B 的订单与库存示例设计

## 目标与范围

在现有 Maven 多模块工程中新增两个独立运行的 Spring Boot 服务，为后续分布式事务实验准备真实的跨服务数据库写入链路。用户已确认采用订单服务 A 调用库存服务 B 的方案。本阶段只实现各服务本地事务，不实现跨服务原子提交、补偿、幂等重试或分布式事务框架。

沿用工程的 Java 21、Spring Boot、MyBatis-Plus 版本及现有 Web/MyBatis Starter。保留原 jaycong-example 的行为，不引入注册中心、网关、消息队列或额外公共业务模块。

## 模块与运行方式

| 模块 | 默认端口 | 责任 |
| --- | --- | --- |
| jaycong-order-service | 8081 | 保存订单，通过 HTTP 调用库存服务 |
| jaycong-stock-service | 8082 | 查询库存，原子扣减库存 |

两个模块加入根 POM，各自拥有启动类、Controller、Service、Mapper、实体、配置和可执行 JAR。跨服务调用采用 Spring RestClient；B 的地址由配置提供，默认 http://localhost:8082，连接超时默认 2 秒，读取超时默认 5 秒，均可配置，不自动重试。

默认各自使用 H2 内存数据库，进程重启后恢复初始数据。两个服务不能共享 DataSource 或业务表。另提供 mysql profile、独立建表脚本和通过环境变量配置连接的示例，分别使用 jaycong_order 与 jaycong_stock 数据库。MySQL 模式不自动初始化或清空数据库。

## 数据与接口

订单表 demo_order：id（自增主键）、product_id、quantity。库存表 demo_stock：product_id（主键）、available_quantity。默认初始化商品 1、库存 100；不引入商品管理、价格、支付或用户子系统。

所有接口使用现有 Result 包装返回结果，参数通过 Jakarta Validation 校验，业务错误遵循项目现有错误码与异常处理约定。商品 ID、购买数量必须为正数。

### A：订单服务

- POST /orders：请求字段 productId、quantity、failAfterStockDeduction（可选，默认 false）。成功返回生成的订单，包括 id、productId、quantity。
- GET /orders/{id}：返回订单，不存在时返回 404。
- GET /orders：返回按 ID 升序的订单列表，仅用于小规模演示，便于检查失败调用没有产生订单。

failAfterStockDeduction 是本示例专用的故障开关，在 B 返回扣减成功后触发运行时异常。该接口用于本地实验，不作为生产订单接口设计。

### B：库存服务

- GET /stocks/{productId}：返回 productId 和 availableQuantity，不存在时返回 404。
- POST /stocks/deduct：请求字段 productId、quantity，成功返回扣减成功的空结果。

库存扣减使用带 available_quantity >= quantity 条件的单条 UPDATE。检查受影响行数，在同一本地事务内将商品不存在或库存不足转换为明确的业务失败，防止并发调用将库存扣成负数。

## 调用与事务边界

1. 客户端调用 A 创建订单。
2. A 的业务 Service 开启本地事务并插入订单。
3. A 通过 HTTP 调用 B 的扣减接口。
4. B 在自己的本地事务内扣减库存，事务提交后返回成功。
5. A 检查 HTTP 状态及响应体业务状态；确认成功后，正常返回并提交订单事务。
6. 如请求开启故障开关，A 在第 4 步完成后抛出运行时异常，回滚订单事务。

库存不足、B 不可用、超时、非成功 HTTP 响应、空响应或业务失败均使 A 创建订单失败并回滚本地订单。下游错误需转为可理解的业务或服务调用错误，不能把失败响应误当成功。

B 已提交但 A 失败时，库存不会恢复，这是需要保留的演示现象。网络超时同样可能发生在 B 已提交之后，因此超时不能证明库存未扣减。本阶段不重试、不补偿，也不声称重复请求具有幂等性。

## 验收与测试

使用独立测试数据验证以下行为，避免依赖测试执行顺序：

1. 两个服务均能打包为可执行 JAR，分别启动；A 到 B 通过真实 HTTP 通信。
2. 初始库存 100，购买 2 件成功后订单存在，库存变为 98。
3. 库存不足时请求失败，订单未提交，库存不变。
4. B 扣减成功后触发 A 故障：订单未提交，库存减少，能直接观察跨服务不一致。
5. 参数非法时不写入订单或扣库存；未知订单或商品返回明确错误。
6. B 不可用或返回错误时 A 不提交订单；客户端设置有效的超时边界。
7. 并发扣减不产生负库存。

优先采用真实 HTTP 和 H2 的集成测试覆盖关键事务边界，适量单元测试覆盖下游错误响应解析。执行现有工程的 Maven verify，确保原模块仍通过。MySQL 配置与 SQL 提供静态检查；只有存在可用 MySQL 环境并实际运行时才报告 MySQL 联调通过。
