# 术语表

术语用于描述职责，不要求每个术语都对应一个包或类。下列业务名称均为说明示例。

| 术语 | 含义与使用方式 |
|---|---|
| 目标工程 | 用户将要开发或修改的工程，具有自己的业务名、根包、依赖和既有约定 |
| 领域（Domain） | 一组业务知识、规则和行为，例如设备借用的提交、审批和归还规则 |
| 业务模块 | 围绕一项业务能力组织的代码；可以是包、构建子模块或独立部署服务 |
| 领域边界 | 某组规则与数据的责任范围；不与 Maven 模块、数据库或进程边界自动等同 |
| 用例（Use Case） | 用户或系统希望完成的一次业务操作，例如审批一份设备借用申请 |
| Entity | 具有稳定业务身份及生命周期的对象；字段相同也可能是两个不同实体 |
| 聚合 / 聚合根 | 在同一业务一致性范围内一起维护的一组对象及其统一入口；按业务不变量识别，不按表数量机械划分 |
| 值对象 | 由值而非独立身份定义的对象，例如时间区间；不必为每个字段都创建值对象 |
| Domain Service | 组织本领域的加载、权限、约束、幂等、实体调用和持久化协调；本说明书允许其直接使用 Mapper |
| ApplicationService | 完整用例的协调者，组合多个领域、外部系统或恢复步骤；不替代实体规则 |
| Facade | 对外公开某项业务能力的门面；接口是契约，实现放在业务模块中 |
| Controller | HTTP 的接入适配，处理请求、可信身份与响应，调用公开业务入口 |
| API | 调用方可依赖的接口与数据契约；独立 API 模块不包含业务实现 |
| DTO | 跨某个边界传输的数据对象的统称；Request、Response、VO 可以是不同用途的 DTO |
| Request / Response | 一次公开操作的输入和结果，例如 ApproveLoanRequest、LoanResponse |
| VO | 本说明书中指 View Object，即对外查询视图；值对象统一称“值对象”，避免缩写歧义 |
| Param | HTTP 参数对象，仅包含该接口允许客户端提交的字段 |
| DO | Data Object，专用于数据库映射的数据对象；若实体兼任映射对象，不必再创建一套 DO |
| Command | 表达一次操作意图的内部输入，可用于隔离 API 与领域；没有隔离需求时不强制添加 |
| Repository | 面向业务对象的存取抽象；采用纯领域模型时常定义端口并由基础设施实现，轻量方案不强制引入 |
| Persistence Mapper | MyBatis/MyBatis-Plus 的数据访问组件，负责 SQL 与表字段映射 |
| MapStruct Mapper / Convertor | 对象字段转换组件；与执行 SQL 的 Mapper 是不同职责 |
| ORM | 对象与关系数据映射；实体带持久化注解就是一种框架依赖 |
| Channel / Client / Adapter | 对外部能力的技术适配实现，处理 SDK、协议、签名和错误转换 |
| 业务事件 | 已发生事实的数据表达，例如申请已批准；一个事件类本身不提供可靠投递 |
| 操作流水 | 对一次业务操作及其结果的持久化记录，可用于幂等、审计或恢复，不必包含实体全部快照 |
| 幂等 | 同一次操作重复请求，业务结果与执行一次一致；需要定义操作身份及同键不同参数的规则 |
| 乐观锁 | 更新时比较读取版本并检查影响行数，发现并发修改后按业务规则处理冲突 |
| 本地事务 | 一个事务资源范围内的原子提交；普通数据库事务不覆盖任意远程系统 |
| 补偿 | 对已完成步骤采取反向或修正动作，不等于数据库回滚，也未必完全恢复原状 |
| Outbox | 在本地事务中持久化待发送事件，提交后另行投递的方案；仍需处理重复投递与消费 |
| CQRS | 区分命令与查询的建模/处理方式；仅把写服务和读服务分成两个类不代表完整采用 CQRS |
| TCC | 用 Try 预留、Confirm 确认、Cancel 取消组织跨系统步骤的方案，需要业务级实现与幂等设计 |
| BASE | 强调可用与最终一致的一类分布式设计思想；具体注解或框架保证需按实现核实 |

缩写未在表中出现时，首次使用应解释其含义；不要假定目标业务有与示例同名的模块、状态或接口。
